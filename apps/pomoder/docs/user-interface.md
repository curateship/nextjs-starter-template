# User interface

The standalone Pomodoro Dashboard is the visual source of truth: near-black surfaces, tomato accent, Bricolage Grotesque headings, JetBrains Mono timer data, compact navigation, ambient hero media, and restrained borders.

The application is route-based instead of prototype state. Desktop uses a fixed rail and dashboard grid; mobile uses an off-canvas rail and stacked content. All controls use native buttons/inputs, visible focus, labels, meaningful empty/error states, and WCAG AA contrast.

Guest mode exposes the timer, temporary tasks, preferences, pricing, and curated previews. Account, room, upload, billing, and generation actions explain their authentication or Pro requirement instead of silently failing.

Today's tasks form a lightweight focus plan: titles, Low/Normal/High priority, and optional 1–20 Pomodoro estimates are edited inline on the Tasks page, and active tasks are reordered by pointer, touch, or keyboard through per-row drag handles (dnd-kit with screen-reader announcements). Completed tasks group below the active plan, progress renders as `done/estimate pomos`, and the plan — including manual order — persists in browser storage for guests, in `tasks.priority/estimated_pomodoros/sort_order` for accounts, and carries through the daily rollover clone. Reordering is one atomic owner-scoped mutation over today's active set; failed edits and reorders roll back optimistically with a visible error.

Focus rhythm presets switch all four timer values (focus, short break, long break, auto-start) at once. Three built-ins — Classic 25/5/15, Deep Work 50/10/30, Study Sprint 15/3/10 with auto-start — live in code with stable `builtin:` identifiers; up to ten custom presets per user persist in `user_timer_presets` for accounts and versioned `pomoder:presets:v1` browser storage for guests (corrupt payloads are discarded, never repaired). The Settings "Focus rhythm" card hosts the preset picker (shadcn Select, popper-positioned) plus a compact create/edit/delete editor with a shared shadcn confirmation; the header Timer quick controls list the same presets and mirror the live timer over `pomoder:timer-state` events. Applying a preset goes through the one canonical preference path in `usePomodoro`, resets only a fully stopped timer, and is disabled — with an explanation — while a timer is running or paused or when no page hosts the timer; the picker shows the matching preset or "Custom" when values diverge.

The History page is the private focus report: an authenticated range picker (7 days, 30 days, 12 months, this year) drives summary cards, a calendar heatmap, a daily/monthly trend chart, a top-task breakdown, and a paginated completed-session table, all backed by one bounded server report. Every visual chart is aria-hidden with a screen-reader table equivalent, scrollable chart regions are keyboard-focusable, and guests see a sign-in prompt instead of fabricated data. The 12-month and yearly ranges are Pro-gated through server entitlements and render an upgrade panel for free accounts. CSV export downloads the same authorized range with RFC 4180 quoting and formula-prefix escaping; the global leaderboard stays a separate, opt-in surface.

Ambient sound is one shell-level player shared by the header quick controls, the compact header player, and the Sounds catalog. Selections use one canonical reference (`curated:<key>` for the first-party loops in `public/pomoder/audio-*.mp3`, `media:<uuid>` for ready user audio), persist to browser storage for guests and to `user_preferences` for accounts, and never autoplay after a reload — a visible play control resumes instead. Playback failures surface a dismissible notice; unavailable user media stops and clears itself. Optional completion alerts (chime plus browser notification) are enabled only from the Settings toggle, which is the sole place notification permission is requested. Curated loops are regenerated with `node scripts/generate-curated-sounds.mjs`.

Every person in the product is drawn by one component (`ProfileAvatar`): their uploaded picture when they have one, otherwise a deterministic coloured initial taken from the display name shown beside it, so the same person keeps the same colour in room member lists, chat, the leaderboard and the header quick leaderboard. The public room cards stay anonymous — they count the people in a room without naming or picturing them, because that list is readable signed out. Surfaces choose only the diameter, through the `--avatar-size` custom property; the circle, the initial's size and the eight-tone palette live once in `styles.css`. The Settings "Your profile" card owns upload and removal: the browser centre-crops the picked file to a 512px square JPEG before sending it, removal is a single click, and both refresh the router context so the rest of the app updates without a reload. A picture that cannot be loaded — removed by its owner or by a moderator mid-session — falls back to the initial rather than a broken image.
